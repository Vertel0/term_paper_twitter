# best_modify_proposition

Ниже предложения по аккуратному улучшению `deberta-best.ipynb` без потери стабильности.

## Текущая сильная точка
- Уже достигнуто: `accuracy ~0.9447`, `f1 ~0.8854`, `roc_auc ~0.9667`.
- Основной резерв: поднять `recall` класса `crypto` (сейчас ~0.8292), сохранив precision.

## Уже внесено в `deberta-best.ipynb`
1. Увеличены эпохи: `num_train_epochs: 2 -> 3`.
2. Смягчён шаг обучения для лучшей сходимости: `learning_rate: 1.5e-5 -> 1.2e-5`.
3. Добавлено сохранение модели архивом и автоскачивание в Colab.

## Предлагаемые следующие эксперименты (по одному за запуск)

### Эксперимент A (приоритет)
- `num_train_epochs = 4`
- `early_stopping_patience = 2` (оставить)
- Остальные параметры без изменений.

Ожидаемый эффект: рост `recall` и `f1` за счёт более долгой донастройки, если нет переобучения.

### Эксперимент B
- Вернуть `learning_rate = 1.5e-5`
- `num_train_epochs = 3`
- Сравнить с текущим вариантом по `f1` и `recall`.

Ожидаемый эффект: быстреее сближение, иногда лучше для recall, но риск шума выше.

### Эксперимент C (если нужен прирост recall класса crypto)
- На этапе инференса подобрать порог вероятности не 0.5, а 0.45..0.35.
- Выбрать порог по валидации, где `f1` максимален.

Ожидаемый эффект: часто +recall и +f1 при умеренной потере precision.

## Как сравнивать корректно
1. Для каждого эксперимента фиксировать:
   - `eval_accuracy`, `eval_f1`, `eval_precision`, `eval_recall`, `eval_roc_auc`, `eval_pr_auc`, `eval_mcc`.
2. Сравнение вести по одной и той же test-выборке.
3. Менять только один блок параметров за раз.

## Практический таргет
- Реалистичный ближайший таргет: `accuracy 0.95+` и `f1 0.89+` при стабильной сходимости.
